# PDF签名服务性能优化说明

## 优化概览
针对2C2M低配置服务器在处理多页PDF文档时的性能问题，特别是骑缝章处理时的卡顿问题，实施了以下优化措施。

## 主要优化措施

### 1. 批量处理替代逐页签名
- **原方案**：每页独立进行增量签名，页数多时需要多次PDF加载和保存操作
- **新方案**：批量处理所有页面，一次性完成签名操作
- **优化效果**：减少了90%以上的PDF文档加载和保存操作

### 2. 图像缓存机制
- 使用 `ConcurrentHashMap` 缓存已加载的图像和PDImageXObject对象
- 避免重复加载和处理相同的图像资源
- 特别优化了骑缝章切片的缓存策略

### 3. 内存使用优化
- 动态内存策略：根据PDF页数自动选择最优内存使用模式
  - 小文档（<20页）：使用更多内存以提升性能
  - 中等文档（20-50页）：混合模式，平衡内存和性能
  - 大文档（>50页）：纯临时文件模式，最小化内存占用
- 移除了PDFBox 3.x不再支持的MemoryUsageSetting参数

### 4. 并行处理支持
- 对于超过20页的文档，使用线程池并行生成骑缝章切片
- 线程池大小根据CPU核心数自动调整（最多4个线程）
- 通过 `CompletableFuture` 实现异步处理

### 5. 智能处理策略
- 10页以下文档：使用原始逐页签名方法（性能影响小）
- 10页以上文档：自动切换到批量优化处理模式
- 可通过环境变量 `USE_OPTIMIZED_PERFORATION` 控制是否启用优化

## 环境变量配置

```bash
# 控制是否使用优化版本（默认启用）
USE_OPTIMIZED_PERFORATION=true  # 设为false使用原始实现

# PDF内存模式
PDFBOX_MEMORY_MODE=auto  # auto|temp|mixed
PDFBOX_MAX_MAIN_MEMORY_MB=64  # 混合模式时的堆内存缓存大小

# 签名预留空间
SIGNATURE_RESERVED_SIZE=524288  # 签名预留空间大小（字节）
```

## 性能提升预期

基于优化后的实现，在2C2M配置的服务器上：
- **10-50页文档**：处理速度提升3-5倍
- **50-100页文档**：处理速度提升5-10倍
- **100页以上文档**：处理速度提升10倍以上
- **内存占用**：大文档处理时内存占用减少60%以上

## 使用建议

1. **生产环境部署**：建议先在测试环境验证优化效果
2. **监控**：部署后监控CPU、内存和响应时间
3. **调优**：根据实际使用情况调整环境变量参数
4. **回滚**：如遇问题可通过设置 `USE_OPTIMIZED_PERFORATION=false` 快速回滚到原始实现

## 兼容性说明

- 优化代码完全向后兼容
- 保留了原始实现作为备用方案
- 支持通过环境变量灵活切换处理模式
