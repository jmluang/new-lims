# Example LIMS Migration Notes

## Scope

This migration ports the useful domain behavior from `example/` into the new Laravel API and React SPA. The legacy PHP files are reference material only; the new code uses the current project patterns for authorization, audit logs, API controllers, React routes, and tests.

Implemented functional areas:

- Standard library: standards, catalogs, and test items.
- Test orders: one commission order with multiple execution standards and multiple expected sample rows.
- Sample receiving: one order delivery can create multiple physical samples.
- Sample flows: physical samples keep append-only holder/location flow records.

## Key Adaptations

- Standard library delete is implemented as soft disable through `standards.status = disabled`.
- Test orders keep customer snapshot fields and nullable customer links. Snapshot fields do not drift when the customer master record changes.
- Test order children are synced by stable `id`; the new implementation does not delete and reinsert every child row during edits.
- Sample numbers are generated by `SampleNumberService` in the form `{order_no}-{delivery_sequence}-{sample_index}/{delivery_received_count}`.
- `delivery_received_count` is per delivery. It is not cumulative across the full order.
- Rejected receive rows do not create `samples`, do not create `sample_flows`, and do not consume sample indexes. They are recorded in `audit_logs` with action `samples.receive.rejected`.
- Frontend create/edit flows are split from list pages when the form is large: standards, test orders, and sample receiving use dedicated pages.

`CanonicalAcceptanceSeeder` now includes:

- `test_order_manager`: standard read, test order CRUD/export, child-row permissions, and sample receive.
- `sample_manager`: sample read/receive/update/export and sample flow read/create.

Both are acceptance users with password `Password123!`.

## Temperature And Humidity Records

Legacy references:

- `example/temp_humidity.php`
- `example/temp_humidity-1.php`
- `example/post.php`

Target routes:

- `GET|POST /api/device/temp-humidity`
- `GET /api/temp-humidity-records/equipment-lookup`
- `GET /api/temp-humidity-records`
- `POST /api/temp-humidity-records`
- `PUT /api/temp-humidity-records/{tempHumidityRecord}`
- `DELETE /api/temp-humidity-records/{tempHumidityRecord}`

Key adaptations:

- New records keep `equip_no` as a legacy/device snapshot and use nullable `equipment_id` when the equipment exists.
- Equipment lookup resolves placement from `equipment.location_id`, `equipment_locations.parent_id`, and `equipment.legacy_placement`.
- Public device ingest remains GET/POST compatible and enriches known equipment automatically.
- React uses the shared `QrScannerPanel` instead of inline page JavaScript.
